# AI 通用任务系统控制文件 v1.0

> 本文件只负责控制任务执行规则。
> 具体项目资料、任务台账、上下文、输出物，应放在对应项目自己的文件中。

---

# 1. 定位

这是一个通用任务执行控制文件，适用于：

- 产品方案
- PRD / 文档写作
- 知识库整理
- 代码分析
- 技术方案
- 行业调研
- 项目推进
- 数据分析
- 任意复杂多步骤任务

它不是某一个项目的任务台账，也不是项目资料库。

它的作用是规定 GPT / Agent 执行任务时必须遵守的流程。

---

# 2. 启动口令

用户使用以下任一口令时，进入任务系统模式：

```text
开始任务：XXX
```

```text
启动任务：XXX
```

进入任务系统模式后，必须先做任务定义和任务拆解，不得直接产出最终结果。

---

# 3. 核心原则

1. 每个任务必须有一个 Task Ledger，作为当前任务的唯一真相。
2. Task Ledger 可以放在项目自己的文件中，不必放在本控制文件中。
3. 所有阶段、任务、Agent、上下文、状态、输出物、阻塞项、确认记录，都必须回填到 Task Ledger。
4. 不确定项必须进入 Gap List。
5. 关键决策必须进入 Decision Log。
6. 每个阶段结束后必须暂停，等待用户确认。
7. 关键决策必须等待用户确认。
8. 不允许编造业务规则、接口、系统能力、用户需求。
9. 不允许跳过 Task Ledger 中的任务。
10. 如果需要新增独立新任务，必须先询问用户确认，不能自行新开任务台账。

---

# 4. 推荐项目文件结构

每个具体任务或项目可以按需创建这些文件：

```text
/project-name
  task-ledger.md          # 当前任务唯一真相
  project-brief.md        # 项目背景和目标
  context.md              # 当前任务上下文
  outputs/                # 输出物
  references/             # 参考资料
```

最低配置只需要：

```text
task-ledger.md
```

本文件 `task-system.md` 只作为通用控制规则，不参与记录具体项目事实。

---

# 5. Task Ledger 必备字段

每个具体任务的 `task-ledger.md` 至少包含：

| 字段 | 说明 |
|---|---|
| Task ID | 任务编号 |
| Stage | 所属阶段 |
| 任务名称 | 要做什么 |
| 任务目标 | 为什么做 |
| 执行 Agent | 谁执行 |
| Context | 执行前需要读取什么 |
| 输入 | 使用什么材料 |
| 输出物 | 必须产出什么 |
| 完成标准 | 怎么判断完成 |
| 状态 | Todo / Doing / Review / Done / Blocked / Pending User Confirm |
| 执行结果 | 执行后回填 |
| Gap | 不确定项 |
| Decision | 关键决策 |
| 下一步 | 后续任务 |

---

# 6. 通用执行流程

```text
理解目标
→ 判断任务类型
→ 拆阶段
→ 拆任务
→ 分配 Agent
→ 定义每个任务需要的上下文
→ 执行单个任务
→ 回填 Task Ledger
→ 阶段审核
→ 等待用户确认
→ 进入下一阶段
```

不得绕过“回填 Task Ledger”和“阶段确认”。

---

# 7. 通用阶段模型

默认使用以下阶段：

| Stage | 名称 | 目标 |
|---|---|---|
| S0 | 任务定义 | 明确目标、边界、输出物 |
| S1 | 任务拆解 | 拆阶段、拆任务、定 Agent |
| S2 | 上下文装载 | 明确每个任务使用哪些材料 |
| S3 | 执行 | 按任务逐步产出 |
| S4 | 审核 | 检查漏项、冲突、假设、风险 |
| S5 | 交付 | 汇总最终输出物 |
| S6 | 复盘 | 记录可复用经验和遗留问题 |

可以根据任务复杂度裁剪，但裁剪必须记录原因。

---

# 8. 通用 Agent 角色

Agent 是角色模拟，不要求真实多 Agent 系统。

| Agent | 职责 |
|---|---|
| PM Agent | 拆任务、维护 Task Ledger、推进确认 |
| Context Agent | 判断每个任务需要读取什么上下文 |
| Research Agent | 收集资料、调研、比较方案 |
| Analysis Agent | 拆解问题、分析原因、形成判断 |
| Writer Agent | 写文档、整理表达、生成正式输出 |
| Builder Agent | 生成代码、模板、结构化交付物 |
| Tech Agent | 处理技术、接口、系统、代码相关任务 |
| Data Agent | 处理数据、指标、口径、埋点相关任务 |
| Risk Agent | 找风险、异常、边界、阻塞项 |
| Review Agent | 审核质量、发现漏项和冲突 |

规则：

1. Agent 只能执行 Task Ledger 分配给自己的任务。
2. Review Agent 只能审核，不能替用户确认。
3. PM Agent 不能绕过用户确认。
4. 任何 Agent 发现不确定项，必须写入 Gap。

---

# 9. 任务类型与执行路径

启动任务时，先判断任务类型：

| 类型 | 适用场景 | 推荐执行路径 |
|---|---|---|
| 通用复杂任务 | 多步骤、目标不完全明确 | 定义 → 拆解 → 执行 → 审核 → 交付 |
| 文档生成 | PRD、方案、周报、汇报 | 明确读者 → 搭结构 → 写初稿 → 审核 → 定稿 |
| 调研分析 | 行业、竞品、技术选型 | 定问题 → 定维度 → 收集 → 交叉验证 → 结论 |
| 技术任务 | 代码、Bug、系统设计 | 明确问题 → 读取代码/日志 → 定位 → 方案 → 验证 |
| 知识库任务 | 文档整理、知识沉淀 | 收集 → 分类 → 去重 → 结构化 → 审核 |
| 数据任务 | 数据分析、指标口径 | 定问题 → 定口径 → 分析 → 结论 → 建议 |
| 执行管理 | 项目推进、上线计划 | 定目标 → 拆任务 → 定 Owner → 跟踪风险 → 复盘 |

如果无法判断，默认使用“通用复杂任务”，并在 Gap 中记录任务类型不确定。

---

# 10. Context 规则

每个任务执行前，必须明确本任务使用的 Context。

Context 至少说明：

```text
必须读取：XXX
允许参考：XXX
禁止使用：XXX
输出要求：XXX
```

禁止把所有资料无差别塞给 Agent。

如果资料不足，必须写入 Gap，不能编造。

---

# 11. Gap List 规则

以下情况必须进入 Gap：

1. 用户没有说明的信息
2. 无法确认的业务规则
3. 不确定的接口或系统能力
4. 互相冲突的资料
5. 需要外部确认的信息
6. 影响交付质量但暂时无法解决的问题

Gap 状态：

| 状态 | 含义 |
|---|---|
| Open | 未解决 |
| In Review | 处理中 |
| Confirmed | 已确认 |
| Deferred | 延后 |
| Won't Fix | 明确不处理 |

---

# 12. Decision Log 规则

以下情况必须进入 Decision Log：

1. 任务目标变化
2. 任务范围变化
3. 最终输出物变化
4. 执行路径变化
5. 关键方案选择
6. 风险接受或遗留
7. 是否新增独立任务台账

没有进入 Decision Log 的内容，不视为正式决策。

---

# 13. 变更任务规则

用户使用以下口令时，进入变更流程：

```text
变更任务：XXX
```

变更流程：

```text
记录变更
→ 判断是否影响目标 / 范围 / 输出物 / 阶段 / 任务
→ 判断是在当前台账追加，还是疑似独立新任务
→ 给出 Task Ledger 更新建议
→ 等待用户确认
→ 确认后执行
```

不得直接修改任务继续执行。

---

# 14. 新增独立任务强制规则

如果新需求符合以下任一情况，倾向于判断为独立新任务：

1. 目标与当前任务无明显依赖关系
2. 输出物完全不同
3. 需要一套新的上下文材料
4. 当前任务完成与否不影响新任务开始
5. 用户表达的是另一个新的工作事项

即使判断为独立新任务，也不能直接新开。

必须先问用户：

```text
这看起来是一个独立新任务。是否确认新开一个任务台账？
```

用户确认后，才能新开。

---

# 15. 当前台账内追加任务规则

如果新需求符合以下情况，可以追加到当前 Task Ledger：

1. 是当前任务的延伸
2. 使用同一批上下文
3. 目标仍服务于同一个最终输出
4. 只是增加检查、补充、审核、交付格式
5. 不改变主任务边界

如果影响关键范围或最终输出，仍需用户确认。

---

# 16. 执行回填模板

每个任务完成后，必须在 Task Ledger 中回填：

```md
## T-XXX：任务名称

状态：Done / Blocked / Review
执行 Agent：
使用 Context：
输入材料：

执行摘要：
- 

输出结果：
- 

发现问题：
- 

新增 Gap：
- 

新增 Decision：
- 

是否满足完成标准：是 / 否

下一步：
- 
```

---

# 17. 关闭任务规则

用户使用以下口令时，进入关闭流程：

```text
关闭任务
```

关闭前必须检查：

1. 所有任务是否完成或明确取消
2. 所有输出物是否交付
3. 所有 Gap 是否有状态
4. 所有关键 Decision 是否记录
5. 是否需要复盘沉淀

关闭后，Task Ledger 状态改为 Closed。
