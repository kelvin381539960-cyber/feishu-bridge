# AIX Phase 2 方案设计问题清单与决策记录 (QA & Decisions)

本文档记录了 AIX Phase 2 方案设计过程中的关键问答与决策口径，作为 `solution-design.md` 编写的指导依据。

---

### Q1：账本架构设计
**问题**：AIX 账本与 Custody 的关系：AIX 维护独立双记账本，还是以 Custody Provider 余额为权威来源？
**决策**：**采用独立账本 (Double-Entry)**。
- **理由**：独立账本是资金安全的核心保障；支持多 Custody 并存；避免单点故障影响业务；符合监管对账要求。
- **实现**：由独立子系统 `AIX Ledger` 承载，作为资金余额的唯一真相来源 (Source of Truth)，Cobo 等余额报告仅用于每日对账。

### Q2：Custody 地址与归集模型
**问题**：用户链上地址与资金归集如何设计？
**决策**：**独立充值地址 + 异步归集 (Sweeping)**。
- **理由**：对用户展示独立地址确保每笔入金可追溯；收到资金后异步归集至 `Omnibus Pool` 统一管理，降低链上复杂度并提升流动性利用率。
- **实现**：`AIX Ledger` 持续记录每个用户的份额与余额。

### Q3：卡消费币种转换节点
**问题**：用户用稳定币消费法币时，换汇发生在哪个环节？
**决策**：**采用 Float 模型 (选项 A)**。
- **理由**：符合实时授权 SLA 要求 (<200ms)，实现可靠。
- **实现**：AIX 预先在 BIN Issuer 侧存入法币 Float，消费直接扣法币，AIX 定期用稳定币补充 Float。

### Q4：Stablecoin Swap 记账模型
**问题**：USDC ↔ USDT 等稳定币兑换，是否需要真实外部成交，还是由 AIX 内部完成记账转换？
**决策**：**AIX 内部记账转换 (选项 A)**。
- **理由**：零 Gas、秒级成交，用户体验好。
- **实现**：账本原子完成币种扣减与增加。外部流动性获取（补仓）是后台行为，不属于单笔用户兑换路径。

### Q5：未托管钱包 (Unhosted Wallet) 提现策略
**问题**：Travel Rule 无法识别对手方 VASP 时，如何处理？
**决策**：**按金额阈值分级处理 (选项 3)**。
- **实现**：小额放行、大额 EDD、超大额禁止。规则引擎化，支持按市场配置。

### Q6：卡授权超时降级策略
**问题**：AIX 授权系统在 SLA 时间内无响应，BIN Issuer 应如何降级？
**决策**：**默认 Decline (选项 A)**。
- **理由**：保守策略，确保资金安全，避免超额风险。

### Q7：高风险 Step-up 认证方案
**问题**：高风险提现/交易触发 Step-up 时，使用何种认证？
**决策**：**沿用 AAI 生物认证**。
- **实现**：延续 Phase 1 能力，其他方式（FIDO2/OTP 等）作为降级备用。

### Q8：多 BIN Issuer 路由策略
**问题**：如何决定用哪家 BIN Issuer？
**决策**：**可配置路由引擎 (行业规则)**。
- **实现**：支持按注册市场、消费国、卡组织、币种、可用状态等维度配置，预留 Fallback 与不停机更新能力。
